\section{Tujuan Praktikum}
\begin{enumerate}
  \item Mahasiswa mampu memahami konsep arsitektur sistem terdistribusi sederhana dengan memisahkan Web Server dan Database Server pada mesin yang berbeda.
  \item Mahasiswa mampu melakukan konfigurasi layanan MySQL pada server Linux agar dapat menerima koneksi dari jaringan luar (modifikasi bind-address).
  \item Mahasiswa mampu melakukan manajemen user dan hak akses (privileges) MySQL berbasis alamat IP (host-specific) untuk keamanan koneksi.

\end{enumerate}

\section{Dasar Teori}
\subsection{Secure Shell (SSH)}

\par Secure Shell (SSH) adalah protokol yang dirancang untuk menyediakan mekanisme login jarak jauh dan layanan jaringan lain secara aman melalui jaringan yang tidak tepercaya. SSH memfokuskan keamanan pada tiga aspek utama, yaitu kerahasiaan (confidentiality), integritas data (integrity), dan autentikasi pihak yang berkomunikasi. Arsitektur SSH didefinisikan sebagai protokol berlapis yang terdiri dari tiga komponen, yaitu Transport Layer Protocol, User Authentication Protocol, dan Connection Protocol \cite{rfc4251}. Lapisan transport bertanggung jawab melakukan negosiasi algoritma kriptografi, pertukaran kunci, dan autentikasi host server, sehingga terbentuk kanal komunikasi terenkripsi yang menjaga kerahasiaan serta integritas data \cite{rfc4251}. Setelah kanal aman terbentuk, lapisan autentikasi pengguna memverifikasi identitas klien ke server menggunakan beberapa metode, seperti kata sandi maupun kunci publik. Selanjutnya, lapisan koneksi melakukan multiplexing ke dalam beberapa kanal logis (channels) yang memungkinkan berbagai fungsi berjalan di atas satu sesi SSH, misalnya interactive shell, eksekusi perintah jarak jauh, dan port forwarding \cite{rfc4251}.

\par Dalam praktik administrasi sistem, SSH penting karena menggantikan mekanisme remote lama (misalnya telnet) yang mengirim data tanpa enkripsi. Penggunaan SSH juga menekankan verifikasi kunci host (host key) agar klien benar-benar terhubung ke server yang benar. Jika kunci host tidak diverifikasi pada koneksi pertama, sesi dapat menjadi rentan terhadap serangan man-in-the-middle \cite{rfc4251}. Implementasi yang umum digunakan di lingkungan Linux/Unix adalah OpenSSH, yang menyediakan program klien seperti \texttt{ssh} untuk mengakses shell jarak jauh dan daemon \texttt{sshd} pada sisi server untuk menerima koneksi \cite{openssh-manual}. Dengan kombinasi enkripsi, autentikasi, serta kemampuan tunneling, SSH menjadi fondasi utama untuk manajemen VPS dari jarak jauh dan juga mendukung alur kerja pengembangan seperti Remote-SSH pada Visual Studio Code.

\subsection{Virtual Private Server (VPS)}

\par Virtual Private Server (VPS) adalah layanan komputasi berupa server virtual yang berjalan di atas infrastruktur fisik milik penyedia layanan. Disebut “virtual” karena instans VPS hanya menggunakan sebagian dari sumber daya mesin fisik (misalnya CPU, memori, dan penyimpanan) yang dikelola oleh penyedia, tetapi pengguna tetap mendapatkan alokasi sumber daya tersendiri yang dapat digunakan untuk menjalankan aplikasi dan data \cite{aws-vps}. Secara konsep, VPS memanfaatkan virtualisasi sehingga satu server fisik dapat menjalankan banyak mesin virtual. Meskipun berbagi perangkat keras dan hypervisor yang sama, setiap VPS umumnya memiliki sistem operasi sendiri (misalnya Linux/Ubuntu atau Windows) serta ruang konfigurasi terpisah, sehingga antar-tenant tetap terisolasi \cite{ibm-vps}.

\par Dari sisi model layanan, VPS sering diposisikan “di tengah” antara shared hosting dan dedicated server. Pada shared hosting, banyak pengguna berbagi lingkungan aplikasi yang sama sehingga potensi dampak dari “noisy neighbor” lebih besar. Sementara dedicated server menyediakan seluruh mesin fisik untuk satu pengguna, tetapi biayanya lebih tinggi dan skalanya lebih kaku. VPS menawarkan kompromi: kontrol dan fleksibilitas lebih baik dibanding shared hosting, tetapi umumnya lebih hemat dibanding dedicated hosting \cite{aws-vps}. Di banyak provider, VPS juga hadir dalam beberapa skema pengelolaan, seperti managed (penyedia membantu pemeliharaan) dan unmanaged/self-managed (pengguna mengelola instalasi paket, konfigurasi layanan, update, serta keamanan secara mandiri) \cite{aws-vps,ibm-vps}. Karena praktikum ini menuntut instalasi dan konfigurasi manual (Apache, PHP, MySQL, serta manajemen permission), VPS yang bersifat self-managed relevan untuk melatih kemampuan administrasi sistem dan pemahaman bagaimana komponen server web bekerja pada tingkat sistem operasi \cite{ibm-vps}.

\subsection{LAMP Stack}

\par LAMP stack adalah tumpukan perangkat lunak open-source yang umum digunakan untuk membangun dan menjalankan aplikasi web. Nama “LAMP” merupakan akronim dari Linux (sistem operasi), Apache (HTTP server), MySQL (database), dan PHP (bahasa pemrograman untuk web; pada beberapa variasi dapat diganti Perl atau Python) \cite{ibm-lamp}. Pada arsitektur ini, Linux berperan sebagai fondasi sistem yang menyediakan manajemen proses, jaringan, dan filesystem. Apache HTTP Server berperan menerima permintaan (request) dari klien melalui protokol HTTP/HTTPS, lalu menyajikan konten statis maupun meneruskan eksekusi konten dinamis sesuai konfigurasi modul yang digunakan \cite{apache-httpd-docs}.

\par PHP adalah bahasa skrip yang sangat umum dipakai untuk pengembangan web dan dapat disisipkan ke dalam HTML. Pada aplikasi web berbasis PHP, kode dieksekusi di sisi server untuk menghasilkan HTML yang kemudian dikirim ke klien, sehingga klien hanya menerima hasilnya dan tidak mengetahui detail kode sumber di server \cite{php-intro}. Untuk penyimpanan data, MySQL menyediakan sistem manajemen basis data relasional (RDBMS) yang mendukung SQL untuk membuat, memodifikasi, dan mengkueri data aplikasi \cite{ibm-lamp,mysql-refman}. Interaksi antar komponen LAMP pada skenario dinamis dapat dijelaskan sebagai berikut: browser mengirim request ke Apache; ketika request mengarah ke berkas PHP, Apache meneruskan prosesnya ke interpreter PHP; PHP mengeksekusi logika aplikasi dan berkomunikasi dengan MySQL bila membutuhkan data; hasil eksekusi kemudian dikembalikan menjadi respons HTTP ke klien \cite{ibm-lamp}.

\par LAMP banyak dipakai karena komponen-komponennya matang, terdokumentasi, mudah dipasang pada distribusi Linux populer, dan memiliki ekosistem modul/ekstensi yang luas. Praktikum instalasi LAMP pada VPS melatih pemahaman alur request–response, konfigurasi layanan, serta keterkaitan izin akses direktori web server dengan proses eksekusi aplikasi di lingkungan produksi sederhana.

\subsection{Menghubungkan Website PHP ke MySQL}
Setelah user MySQL berhasil dibuat, saya melakukan pengujian koneksi dari PHP yang berjalan di Windows host ke MySQL di Server. Pada tahap ini saya menyesuaikan kembali host pada user MySQL karena alamat IP yang digunakan untuk koneksi berasal dari jaringan yang berbeda. Saya menghapus user sebelumnya, lalu membuat ulang user dengan host yang sesuai, memberikan hak akses, dan menerapkan perubahan seperti pada Kode~\ref{lst:recreate-user-host}. Setelah itu, saya menyiapkan skrip PHP untuk menguji koneksi menggunakan Kode~\ref{lst:koneksi-php-awal}.

\par Perubahan itu dilakukan karen saya salah melihat alamat IP host yang digunakan untuk koneksi. Alamat IP yang benar adalah \texttt{10.33.34.6}, bukannya \texttt{192.168.56.1}. Oleh karena itu, saya perlu membuat ulang user MySQL dengan host yang benar agar koneksi dari PHP dapat berhasil. Setelah penyesuaian tersebut, saya menulis kode PHP untuk menguji koneksi ke MySQL Server menggunakan kredensial yang sudah disiapkan.

\begin{lstlisting}[style=vscode-dark,language=SQL,caption={Membuat ulang user MySQL dengan host yang sesuai untuk pengujian PHP},label={lst:recreate-user-host}]
DROP USER 'praktikan_host'@'192.168.56.1';
CREATE USER 'praktikan_host'@'10.33.34.6' IDENTIFIED BY '123123123';
GRANT ALL PRIVILEGES ON *.* TO 'praktikan_host'@'10.33.34.6';
FLUSH PRIVILEGES;
\end{lstlisting}

\begin{lstlisting}[style=vscode-dark,language=PHP,caption={Kode PHP untuk menguji koneksi ke MySQL Server},label={lst:koneksi-php-awal}]
<?php
$koneksi = mysqli_connect("10.33.35.96", "praktikan_host", "123123123", "fauzan");

if ($koneksi) {

  echo "<h1>Sukses le!!! Berhasil terhubung</h1>";

  }

\section{Kesimpulan}
\par Berdasarkan praktikum yang telah dilakukan, dapat disimpulkan bahwa instalasi web server dan database server pada mesin yang berbeda dapat diimplementasikan dengan baik selama baik dari, konfigurasi jaringan dan layanan, sudah dilakukan secara tepat. Perubahan nilai \texttt{bind-address} pada MySQL memungkinkan database server menerima koneksi dari luar mesin lokal, sehingga komunikasi antar layanan pada dua mesin yang berbeda dapat berjalan.

\par Praktikum ini juga menunjukkan bahwa pengaturan user MySQL berbasis alamat IP host merupakan langkah penting untuk menjaga keamanan akses database. Dengan membuat user yang hanya diizinkan terhubung dari alamat IP tertentu, akses ke database dapat dibatasi sesuai kebutuhan. Selain itu, pemberian hak akses menggunakan perintah \texttt{GRANT} dan penerapan perubahan melalui \texttt{FLUSH PRIVILEGES} memastikan user yang dibuat dapat digunakan untuk proses koneksi secara benar.

\par Hasil akhir pengujian memperlihatkan bahwa aplikasi PHP pada komputer host berhasil terhubung ke MySQL di server dan mampu menampilkan data dari tabel \texttt{mahasiswa}. Dengan demikian, tujuan praktikum untuk memahami konsep pemisahan web server dan database server, melakukan konfigurasi MySQL agar dapat diakses dari jaringan luar, serta menghubungkan PHP ke database pada mesin yang berbeda telah tercapai.
