\section{Tujuan Praktikum}
\begin{enumerate}
  \item Mahasiswa mampu menggunakan REST API dari Server Ubuntu yang telah dibuatnya di aplikasi front-end yang berada di komputer/laptop yang berbeda dari Server Ubuntu.
  \item Mahasiswa mampu memodifikasi aplikasi front-end guna menambahkan fungsionalitas insert, update, delete data di database lokal.

\end{enumerate}

\section{Dasar Teori}

\subsection{REST API}
\par REST API atau \textit{Representational State Transfer Application Programming Interface} adalah antarmuka pemrograman aplikasi yang mengikuti prinsip-prinsip arsitektur REST. REST sendiri diperkenalkan oleh Roy Fielding sebagai gaya arsitektur untuk sistem hipermedia terdistribusi, dan kemudian menjadi salah satu pendekatan yang paling banyak digunakan dalam pengembangan layanan web modern \cite{ibm-rest-api,restfulapi-rest}. Pada pendekatan ini, data dan fungsi dipandang sebagai \textit{resource} yang diidentifikasi melalui URI, lalu diakses atau dimanipulasi menggunakan antarmuka yang seragam. Karena sifatnya ringan, fleksibel, dan mudah diintegrasikan dengan berbagai bahasa pemrograman serta format data, REST API banyak digunakan untuk pertukaran data antara frontend, backend, layanan web, maupun database \cite{ibm-rest-api}.

\par Sebuah REST API yang baik dibangun berdasarkan sejumlah kendala arsitektural utama, yaitu \textit{uniform interface}, \textit{client-server}, \textit{stateless}, \textit{cacheable}, \textit{layered system}, dan \textit{code on demand} sebagai sifat opsional \cite{ibm-rest-api,restfulapi-rest}. Prinsip \textit{client-server} menekankan pemisahan tanggung jawab antara sisi klien dan sisi server, sehingga antarmuka pengguna dapat berkembang secara independen dari logika dan penyimpanan data di server. Sementara itu, sifat \textit{stateless} mengharuskan setiap request membawa seluruh informasi yang dibutuhkan untuk diproses, tanpa bergantung pada sesi yang disimpan di server. Pendekatan ini membuat REST API lebih sederhana, mudah diskalakan, dan lebih cocok digunakan pada arsitektur sistem terdistribusi \cite{ibm-rest-api,restfulapi-rest}.

\par Dalam implementasinya, REST API sangat sering berjalan di atas protokol HTTP, walaupun REST dan HTTP bukanlah hal yang sama \cite{restfulapi-rest}. Pada praktik umum, method HTTP seperti \texttt{GET}, \texttt{POST}, \texttt{PUT}, dan \texttt{DELETE} digunakan untuk mendukung operasi \textit{create}, \textit{read}, \textit{update}, dan \textit{delete} pada resource. Data hasil pertukaran biasanya direpresentasikan dalam format JSON karena mudah dibaca oleh manusia maupun mesin, serta bersifat independen terhadap bahasa pemrograman \cite{ibm-rest-api}. Selain itu, request dan response juga memanfaatkan header, parameter, serta status code HTTP untuk menyampaikan metadata, otorisasi, keberhasilan proses, maupun informasi kesalahan. Oleh karena itu, REST API sangat sesuai digunakan pada praktikum ini karena memudahkan komunikasi antara backend di server VPS dan frontend di komputer host.

\subsection{MySQL}
\par MySQL adalah sistem manajemen basis data relasional (RDBMS) yang menggunakan Structured Query Language (SQL) untuk melakukan definisi skema, manipulasi data, dan query. MySQL menerapkan arsitektur client--server, di mana proses server (\texttt{mysqld}) menyimpan serta mengelola data, sedangkan klien (misalnya \texttt{mysql}) digunakan untuk terhubung dan mengeksekusi perintah SQL. Dalam praktik pengembangan aplikasi, MySQL banyak dipakai karena performanya baik, dukungan ekosistem luas, serta ketersediaan dokumentasi yang lengkap \cite{mysql-refman}.

\par Pada sisi administrasi sistem, konfigurasi MySQL umumnya dilakukan melalui berkas konfigurasi (misalnya \texttt{mysqld.cnf} di Linux atau \texttt{my.ini} di Windows) untuk mengatur parameter layanan seperti port, direktori data, serta kebijakan akses jaringan melalui \texttt{bind-address}. Selain itu, MySQL memiliki mekanisme autentikasi dan hak akses (privileges) untuk memastikan hanya user tertentu yang dapat mengakses database sesuai perannya \cite{mysql-refman}.

\section{Hasil dan Pembahasan}

\par Pada pertemuan kali ini saya melakukan implementasi sinkronisasi database MySQL antara komputer Windows (sebagai database lokal) dan Ubuntu Server/VPS (sebagai database di server) menggunakan REST API. Sinkronisasi ini bertujuan agar data mahasiswa pada aplikasi front-end di laptop dapat menampilkan dua sumber data (lokal dan server) serta setiap perubahan data (\textit{insert}, \textit{update}, \textit{delete}) yang dilakukan di sisi lokal dapat diteruskan ke server melalui request REST API.

\par Sebelum memulai praktikum, saya menginstal \textit{phpMyAdmin} pada server untuk memudahkan melihat database dan tabel secara visual (tanpa harus selalu menggunakan MySQL CLI). Dengan bantuan phpMyAdmin, saya dapat melakukan pengecekan struktur tabel, isi data, dan proses import file \texttt{.sql} dengan lebih cepat.

\par Secara ringkas, langkah-langkah yang saya lakukan adalah sebagai berikut:
\begin{enumerate}
  \item Menyiapkan phpMyAdmin untuk memudahkan proses pengecekan database, baik di sisi server (VPS Ubuntu) maupun di komputer lokal.
  \item Menyamakan database awal antara VPS dan lokal dengan mengimpor \path{mahasiswa.sql} sehingga isi tabel \texttt{mahasiswa} konsisten.
  \item Menggunakan backend REST API mahasiswa yang sudah dibuat pada pertemuan sebelumnya di VPS, yaitu folder \texttt{resource/sait\_api}. Pada praktikum ini, file API di server tidak banyak diubah karena sudah dikerjakan di pertemuan-pertemuan sebelumnya.
  \item Mengonfigurasi aplikasi client (front-end) pada laptop (folder \path{resource/sait_client_case6}) agar dapat terhubung ke database lokal dan dapat mengakses endpoint REST API di VPS.
  \item Menyesuaikan alamat endpoint REST API pada sisi client (mengganti API address) agar mengarah ke VPS yang digunakan pada praktikum ini.
  \item Membuat dashboard yang menampilkan daftar mahasiswa dari dua sumber: database lokal Windows (query SQL langsung) dan database VPS Ubuntu (hasil response REST API).
  \item Menambahkan fitur CRUD pada aplikasi client: \textit{insert}, \textit{update}, dan \textit{delete} pada database lokal, lalu meneruskan perubahan yang sama ke VPS melalui REST API.
  \item Melakukan pengujian end-to-end dan verifikasi hasil menggunakan phpMyAdmin serta tampilan aplikasi di browser.
\end{enumerate}

\subsection{Struktur Backend dan Frontend yang Digunakan}
\par Praktikum ini menggunakan dua bagian utama proyek, yaitu backend REST API yang berjalan di VPS Ubuntu dan frontend yang dijalankan di komputer. Struktur folder yang digunakan pada laporan ini adalah:

\subsection{Konsistensi \texttt{id\_mhs} antara Lokal dan VPS}
\par Pada sinkronisasi \textit{update} dan \textit{delete}, parameter yang paling penting adalah \texttt{id\_mhs}. Agar operasi \textit{update} dan \textit{delete} benar-benar memodifikasi baris data yang sama pada kedua database, maka nilai \texttt{id\_mhs} pada data lokal dan VPS harus konsisten. Jika nilai \texttt{id\_mhs} berbeda (misalnya karena perbedaan auto-increment atau data awal yang belum sama), maka update/delete bisa saja berjalan pada database lokal, tetapi tidak mengenai baris yang sama pada database VPS.

\par Oleh karena itu, langkah yang saya lakukan adalah memastikan data awal kedua database dibuat sama terlebih dahulu dengan (\textit{initial seeding} melalui import \texttt{mahasiswa.sql}) dan selalu melakukan operasi CRUD melalui satu alur aplikasi yang sama, sehingga perubahan yang terjadi dapat tetap sinkron.

\section{Kesimpulan}

\par Kesimpulan dari praktikum sinkronisasi database MySQL menggunakan REST API adalah sebagai berikut:
\begin{enumerate}
  \item Aplikasi client pada Windows berhasil menampilkan data mahasiswa dari dua sumber, yaitu database lokal (query SQL langsung) dan database server Ubuntu (melalui REST API). Hal ini dibuktikan dengan tampilan dashboard yang memperlihatkan dua tabel data mahasiswa yang berbeda sumber namun memiliki struktur data yang sama.
  \item Sinkronisasi perubahan data (CRUD) berhasil diterapkan dengan pola: simpan perubahan ke database lokal, lalu kirim request REST API agar perubahan yang sama diterapkan di VPS. Proses insert, update, dan delete dapat dijalankan dari frontend dan menghasilkan response status dari REST API.
  \item Pengecekan dan validasi data menjadi lebih mudah dengan bantuan phpMyAdmin, baik untuk memastikan hasil import \texttt{mahasiswa.sql} maupun untuk memverifikasi perubahan data setelah operasi CRUD.
  \item Terdapat catatan penting bahwa operasi update/delete sangat bergantung pada konsistensi \texttt{id\_mhs} antara data lokal dan VPS. Karena itu diperlukan \textit{initial seeding} dan disiplin alur perubahan data agar sinkronisasi bekerja dengan benar.
\end{enumerate}

\par Berdasarkan tujuan praktikum dan percobaan pada pertemuan ini, saya berhasil memahami cara memanfaatkan REST API mahasiswa yang di-host pada VPS Ubuntu serta menggabungkannya dengan database lokal pada aplikasi frontend di laptop. Dengan demikian, aplikasi dapat menampilkan data dari dua sumber sekaligus dan menjaga sinkronisasi perubahan data melalui mekanisme request REST API.
