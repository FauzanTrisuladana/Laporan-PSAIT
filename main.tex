\section{Tujuan Praktikum}
\begin{enumerate}
  \item Mahasiswa mampu memahami konsep External API (Public API) dan perbedaannya dengan Local API yang telah dibangun sebelumnya.
  \item Mahasiswa mampu membaca dokumentasi teknis dari penyedia layanan API pihak ketiga (Open-Meteo) untuk menentukan parameter request yang dibutuhkan.
  \item Mahasiswa mampu mengimplementasikan fungsi HTTP Request pada PHP (menggunakan \texttt{file\_get\_contents} atau cURL) untuk mengambil data dari server eksternal.
  \item Mahasiswa mampu melakukan parsing (penguraian) data JSON yang kompleks dari pihak ketiga menjadi struktur data (Array/Object) yang dapat dibaca oleh aplikasi.
  \item Mahasiswa mampu menyajikan data dari dua sumber berbeda (Database Lokal dan API Internet) dalam satu tampilan dashboard yang terintegrasi.
\end{enumerate}

\section{Dasar Teori}
\subsection{REST API}

\par REST API atau \textit{Representational State Transfer Application Programming Interface} adalah antarmuka pemrograman aplikasi yang mengikuti prinsip-prinsip arsitektur REST. REST sendiri diperkenalkan oleh Roy Fielding sebagai gaya arsitektur untuk sistem hipermedia terdistribusi, dan kemudian menjadi salah satu pendekatan yang paling banyak digunakan dalam pengembangan layanan web modern \cite{ibm-rest-api,restfulapi-rest}. Pada pendekatan ini, data dan fungsi dipandang sebagai \textit{resource} yang diidentifikasi melalui URI, lalu diakses atau dimanipulasi menggunakan antarmuka yang seragam. Karena sifatnya ringan, fleksibel, dan mudah diintegrasikan dengan berbagai bahasa pemrograman serta format data, REST API banyak digunakan untuk pertukaran data antara frontend, backend, layanan web, maupun database \cite{ibm-rest-api}.

\par Sebuah REST API yang baik dibangun berdasarkan sejumlah kendala arsitektural utama, yaitu \textit{uniform interface}, \textit{client-server}, \textit{stateless}, \textit{cacheable}, \textit{layered system}, dan \textit{code on demand} sebagai sifat opsional \cite{ibm-rest-api,restfulapi-rest}. Prinsip \textit{client-server} menekankan pemisahan tanggung jawab antara sisi klien dan sisi server, sehingga antarmuka pengguna dapat berkembang secara independen dari logika dan penyimpanan data di server. Sementara itu, sifat \textit{stateless} mengharuskan setiap request membawa seluruh informasi yang dibutuhkan untuk diproses, tanpa bergantung pada sesi yang disimpan di server. Pendekatan ini membuat REST API lebih sederhana, mudah diskalakan, dan lebih cocok digunakan pada arsitektur sistem terdistribusi \cite{ibm-rest-api,restfulapi-rest}.

\par Dalam implementasinya, REST API sangat sering berjalan di atas protokol HTTP, walaupun REST dan HTTP bukanlah hal yang sama \cite{restfulapi-rest}. Pada praktik umum, method HTTP seperti \texttt{GET}, \texttt{POST}, \texttt{PUT}, dan \texttt{DELETE} digunakan untuk mendukung operasi \textit{create}, \textit{read}, \textit{update}, dan \textit{delete} pada resource. Data hasil pertukaran biasanya direpresentasikan dalam format JSON karena mudah dibaca oleh manusia maupun mesin, serta bersifat independen terhadap bahasa pemrograman \cite{ibm-rest-api}. Selain itu, request dan response juga memanfaatkan header, parameter, serta status code HTTP untuk menyampaikan metadata, otorisasi, keberhasilan proses, maupun informasi kesalahan. Oleh karena itu, REST API sangat sesuai digunakan pada praktikum ini karena memudahkan komunikasi antara backend di server VPS dan frontend di komputer host.

\section{Public API}
\par Public API (sering juga disebut \textit{open API} atau \textit{public web API}) adalah API yang disediakan untuk diakses oleh pihak luar (developer atau aplikasi pihak ketiga) melalui jaringan, umumnya menggunakan protokol HTTP, dengan endpoint serta format request dan response yang telah didefinisikan \cite{ibm-api}. Dengan adanya public API, sebuah organisasi dapat membuat data atau fungsionalitas tertentu tersedia bagi konsumen eksternal tanpa harus mengekspos detail internal sistem secara penuh \cite{ibm-api}.

\par Berdasarkan kebijakan rilisnya, API dapat dibedakan menjadi private/internal API (hanya untuk kebutuhan internal), partner API (hanya untuk mitra tertentu), dan public API (tersedia untuk umum) \cite{redhat-api,postman-what-is-api}. Karena public API ditujukan untuk banyak pengguna, dokumentasi yang komprehensif menjadi sangat penting agar konsumen API memahami endpoint yang tersedia, parameter yang didukung, serta struktur data respons \cite{ibm-api}. Selain itu, public API umumnya menerapkan kontrol akses dan pengelolaan penggunaan (misalnya autentikasi/otorisasi, kuota atau rate limit) untuk menjaga keamanan dan stabilitas layanan \cite{redhat-api}.

\section{Kesimpulan}
\par Berdasarkan tujuan praktikum dan percobaan pada pertemuan ini, saya berhasil memahami konsep External API (Public API) serta cara mengintegrasikannya bersama Local APi (yang saya hosting di vps baru) (REST API mahasiswa) pada satu aplikasi frontend di laptop saya.

\par Selain itu, saya berhasil membaca dokumentasi teknis Jikan API untuk menentukan endpoint dan parameter yang digunakan, kemudian mengimplementasikan HTTP request pada PHP menggunakan \texttt{file\_get\_contents} untuk mengambil data Top Anime. Data JSON yang diterima berhasil diuraikan (parsing) menjadi struktur Array/Object dan ditampilkan pada dashboard dalam bentuk kartu anime yang memuat informasi relevan seperti \texttt{title}, \texttt{rank}, \texttt{score}, \texttt{type}, \texttt{episodes}, \texttt{year}, dan \texttt{image\_url}. Dengan demikian, data dari dua sumber berbeda (REST API mahasiswa dan API publik Jikan) dapat disajikan dalam satu tampilan yang terintegrasi.
